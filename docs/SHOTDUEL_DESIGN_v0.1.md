# SHOT DUEL（Web）· 游戏设计文档 v0.1

> 本文档整理自设计讨论定稿。在此之前的一切实现（tkinter 版、web 原型）视为探索；
> 本文档是后续 Web 化的唯一依据。配套：`GAMEPLAY_V0.3.md`（物理与教学原则）、
> `web/check-levels.js`（关卡可解性门禁）。

## 0. 一句话定义

**2D Physics Basketball Roguelike**
玩家通过控制篮球的初速度、角度、旋转，让篮球穿过复杂环境进入篮筐。

主角不是球员，是**篮球轨迹**。

### 核心哲学：少规则，深组合

第一版只需要 10 个元素：篮球、篮筐、重力、墙、杆、方块、移动物、
角度、力量、旋转。如果这 10 个东西组合起来已经好玩，项目就有根了。

每加一个新东西，先过三问：

1. 它创造了新的决策吗？
2. 它能和已有机制组合吗？
3. 玩家能在一两次尝试内理解它吗？

**禁入清单**（直到三问全过）：传送门、黑洞、重力反转、冰面、激光、
风扇、时间暂停、多球、引力场。

## 1. 核心循环

```text
观察关卡 → 理解障碍 → 规划轨迹 → 投球 → 观察反弹
   → 成功 / 失败 → 获得新的能力 → 进入更复杂的关卡
```

## 2. 投篮操作（锁定）

| 输入 | 动作 |
|---|---|
| 鼠标拖动 | 方向 = 出手角度，距离 = 力量（弹弓式） |
| 鼠标滚轮 | 旋转 |
| 松开鼠标 | 出手 |

不采用 WASD + Space。力度曲线 `p^0.72`（前快后慢），
满拖射程必须 ≥ 1.6 倍最远篮距。

## 3. 物理层：Believable Physics（可信物理）

底层遵守可信的二维物理，游戏层允许简化——目标是**可信而可读**，
不是现实模拟。

* 重力持续作用；矩形障碍用圆-矩形简化碰撞；
* 反射 = 入射 × 材质恢复系数，不同材质不同系数；
* 自旋先作为反弹方向的小幅修正，Magnus/摩擦后置。

材质表（v0.3 只启用 Normal，其余预留）：

| 材质 | restitution | 语义 |
|---|---|---|
| Normal | 0.78 / 落地 0.64 | 普通墙 |
| Bouncy | 1.05 | 弹力墙（预留） |
| Glass | 0.95 | 光滑面（预留） |

## 4. 三层架构（代码纪律）

```text
GAME LAYER    Map / Run / Reward / Boss / Shop / Build
PUZZLE LAYER  Obstacles / Goals / Rules / Level Data
PHYSICS LAYER Gravity / Collision / Spin / Velocity
```

现状：web/app.js 三层混在一个文件里（原型可接受）。
拆分计划：`physics.js`（simulate/tick 共享给预览与实飞）、
`puzzle.js`（关卡数据与校验）、`game.js`（run 循环）。
关卡已经是数据（levels 数组），目标格式向 JSON 关卡文件靠拢。

## 5. 障碍规则（v0.3 锁定 4 种）

**一个障碍 = 一个新的物理问题。**

| 障碍 | 教玩家什么 | 高度纪律 |
|---|---|---|
| 墙 wall | 反弹 | 顶 ≥ 篮筐高度 |
| 杆 bar | 弧线 | 顶 ≥ 篮筐高度 |
| 方块 block | 通道规划 | 与墙/杆组合出通道 |
| 移动物 | 时机 | 最高点 ≥ 篮板高度 |

**高度纪律是硬规则**：不允许出现"平推式低弧就能解"的关卡。

当前 5 关参数与实测解出率（`node web/check-levels.js`，
角度 20-80° × 力度 0.2-1.0 全网格）：

| 关 | 名 | 障碍 | 解出率 | 最省力解 |
|---|---|---|---|---|
| 1 | 起点 | 无 | 8.0% | 48° @ 64% |
| 2 | 弧高 | 杆（顶=筐高+45px） | 5.8% | 50° @ 64% |
| 3 | 反弹 | 墙 | 7.2% | 58° @ 52% |
| 4 | 通道 | 双方块+通天墙 | 4.3% | 60° @ 44% |
| 5 | 时机 | 移动杆（顶=篮板高度）+墙 | 4.9% | 50° @ 64% |

门禁：解出率 0% 的关卡禁止上线；解出率显著高于上一关的"进阶关"需要说明理由。

## 6. 关卡难度曲线

**增加的是决策复杂度，不是数值。**（借鉴杀戮尖塔）

```text
L1 篮筐            学习投篮
L2 篮筐 + 杆        学习弧线
L3 篮筐 + 墙        学习反弹
L4 篮筐 + 杆 + 墙   学习组合
L5 通道             学习轨迹规划
L6 反弹 → 通道 → 篮筐  连续反弹组合（示例）
```

10 节点 run：L1-L4 教学曲线 → 节点 5 精英（强化版关卡）→
L6-L9 组合变体 → 节点 10 Boss（多机制复合 + 收紧的出手窗口）。

## 7. 失败与奖励（v0.1 锁定）

* **每关 3 次出手**。不是无限尝试。
* 普通关：第 1 次失手免费（只重置），第 2、3 次失手各 -1 HP。
* 精英关（节点 5）：无免费，每次失手 -1 HP。
* Boss（节点 10）：失败即 Run 结束。
* 命中奖励：筹码 = 得分，PERFECT（偏心/入射角达标）额外 +2——维持现状。
* 关卡通过后：三选一升级（见 §9），然后自动进入下一关。
* **v0.3 当前实现**（与本节目标规则的差异）：每关 MAX_ATTEMPTS=5 次尝试
  计量条（用完可重置本关，HP 经济未启用，列为候选）；**物理耦合 build
  已实装**——bankShot（恢复系数 +0.07/层）、spinMaster（旋转影响
  ×(1+0.8/层)）、secondChance（首次碰筐反弹复活），与 §9 原则一致。

## 8. 预测轨迹：可见，但不是完整答案

* 预测线常驻（谜题模式的草稿纸），**只画到第一次碰撞为止**，且最长
  80 步视野（`PREVIEW_HORIZON`，不显示最终落点）；
* 碰撞后的完整路线不显示；
* 未来风/旋会引入显示误差；
* 某些 Build 能力可以扩大预测范围（见 §9 鹰眼）。

瞄准本身就是 Gameplay。

## 9. Build：升级必须与物理耦合

现有 8 张升级（稳定器/热手/旋转大师/柔和篮筐/风阻外套/高点出手/
保险/赞助）保留——它们改的都是物理与执行条件。

下一批候选（每张都直接动物理，禁止"直接 +X% 命中率"）：

| 升级 | 效果 |
|---|---|
| 🎯 自动修正 | 预测轨迹距篮筐 ≤ 0.5m 时，自动修正 2° |
| 🌀 旋转大师（强化） | 自旋对反弹方向的影响 ×2 |
| 🧲 吸框 | 筐口附近的球轻微向篮筐偏转 |
| 🪃 二次弹跳 | 第一次撞墙后恢复系数 +0.15 |
| 👁 鹰眼 | 预测线延长覆盖一次碰撞后的轨迹 |

**双通道原则**：操作流（玩家真的准）不需要太多辅助；
Build 流（操作一般）靠能力降低难度。两条路都通向通关。

## 10. Roguelike 地图

v0.3：线性 10 节点（§6）。
v0.4 候选：分支地图（每 3 关三选一路线）、事件节点、筹码商店
（卖升级 / 额外出手机会 / 预测延长）。

## 11. 训练模式

训练场分项训练：Angle（30°-70°）/ Power（0-100）/ Spin（±）/ Distance（2m-15m）。
目的：让玩家建立"这个距离大概 52°、82% Power"的直觉——训练的价值。

## 12. 美术风格

* 深色球场 + 语义色（障碍带名字标签：ARC / BOUNCE / 通道）；
* 线条火柴人；新机制必须可读——玩家看到障碍就知道它的物理含义；
* 表情与粒子在核心操作稳定后再加。

## 13. 未来路线（明确不在 v0.3）

* 材质障碍（Bouncy/Glass 混入关卡）；
* 程序化关卡生成：随机组合障碍 → solver 验证（0% 丢弃、2% 困难、70% 太简单）→
  生成关卡——check-levels.js 是 solver 的雏形；
* 训练场；
* 移动篮筐 / 缩小篮筐（复用 tkinter 引擎的规则变体）。
