# SHOT DUEL v0.3 Gameplay Foundation

## Core fantasy

玩家不是单纯把球投进篮筐，而是在有限的物理规则下，设计一条能到达篮筐的篮球轨迹。

核心循环：

观察关卡 → 选择角度/力量/旋转 → 预测轨迹 → 出手 → 观察碰撞 → 根据结果调整 → 进入下一关。

## 第一版输入

- 鼠标拖动：拖动方向决定出手角度，拖动距离决定力量。
- 鼠标滚轮：调整旋转。
- 松开鼠标：出手。

## 第一版物理

底层遵守可信的二维物理规律：

- 重力持续作用；
- 矩形障碍使用简化碰撞检测；
- 碰撞使用可控恢复系数，而不是完全弹性；
- 地面、墙体会损失部分能量；
- 旋转先作为反弹方向的小幅修正，后续再加入更完整的 Magnus/摩擦模型。

原则是“可信而可读”，不是追求现实世界的完整模拟。

## 第一版关卡语言

每种障碍只负责教玩家一个问题：

| 关卡语言 | 玩家学习 |
| --- | --- |
| 无障碍 | 基础角度与力量 |
| 地面杆 | 提高弧线 |
| 反弹墙 | 利用碰撞改变方向 |
| 方块通道 | 规划连续轨迹 |
| 移动障碍 | 观察时机 |

暂不加入黑洞、传送、重力反转、激光等超现实机制。

## 视觉反馈

第一版只需要：

- 球场；
- 简化球员；
- 篮筐和篮网；
- 篮球飞行轨迹；
- 预测轨迹；
- 障碍物；
- 命中/失败文字反馈。

角色表情和粒子效果可以在核心操作稳定后逐步加入。

## Shooting Lab

每次出手记录：

- 距离；
- 出手角度；
- 力量；
- 旋转；
- 最高点；
- 碰撞次数；
- 最终结果。

目的不是给玩家一个“随机升级”，而是让玩家理解自己的错误。

## 后续扩展原则

新机制必须至少满足以下一项：

1. 创造新的投篮决策；
2. 能与已有物理机制形成组合；
3. 玩家可以在一次或两次尝试中理解规则。

如果只是增加数值或视觉复杂度，则不优先加入。
